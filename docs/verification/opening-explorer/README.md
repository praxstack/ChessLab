# Local opening explorer evidence

Openings now combines the existing 3,810 named lines with an interactive game explorer. Position-based move counts and White/draw/Black result bars include transpositions. Board clicks, dragging, typed SAN/UCI, promotions, navigation and flip share the existing legal chess board. Examples replay full games, return to the previous exploration, or open a new owned study through the existing draft-safe import flow. My Games is restricted to the signed-in user's completed standard games, including local bot games.

The [official workflow](https://support.chess.com/en/articles/8708732-how-do-i-use-the-game-explorer) and [position identity guide](https://support.chess.com/en/articles/8709003-does-move-order-matter-when-looking-at-a-position-in-explorer) informed this increment. The public data is the [Lichess Elite November 2025 archive](https://database.nikonoel.fr/), derived from CC0 Lichess exports. Its 280,246 source game headers all date to November 2025, have unique source URLs, and meet the stated 2500+/2300+ rating selection. The parser's accepted/rejected totals are recorded separately; this is an online selected corpus, not Chess.com's master database.

The complete archive remains local. A pinned isolated python-chess 1.11.2 importer streams it, validates each entire accepted main line, rejects malformed/nonstandard/unfinished games, and atomically publishes an integrity-checked SQLite database without overwriting an existing file. The server opens that database read-only. The first 60 half-moves are indexed; a game contributes its first encounter with a position, including castling and legal en-passant rights but excluding move counters. Up to three examples per continuation are stored, and the UI shows up to twelve across the most frequent continuations. Results describe the corpus, not an engine evaluation or a prediction of move strength.

No web-runtime dependency was added. The app reuses React, Express, chess.js, native SQLite, shared board controls and study serialization. Private game indexing is cached per account and invalidated by completed-game revisions; the existing 500-game account ceiling bounds this local workload. Corpus queries use their indexed position key. Original games, nested studies, review practice, puzzles and account data remain protected by the existing suite.

Root inspected initial desktop and phone layouts using synthetic games. A missing matching Playwright browser binary was restored using the pinned installation's official installer, with existing browser garbage collection disabled; no other browser installation was removed. This preliminary preview is retained under ignored `.scratch/opening-explorer` and is not the accepted full-corpus proof.

Independent acceptance remains unavailable: the installed Astra Team gate rejected this native task runtime at 07:50 UTC. Astra Cursor Team uses the same identity validator; its requirement was preserved. The existing installed unslop skill-manifest drift also remains. Exact failures are retained under checks. No validator, model identity, governing policy or acceptance gate was changed. Full platform parity, the original conversational tutor, later human multiplayer and billing remain active.

The complete legality import accepted 280,155 games and excluded 91 unfinished/empty games. During root review, a stricter token layer was added to reject malformed move text and null moves in future imports. The entire original archive then passed that exact lexical layer separately: 7,655,602 lines, no unrecognized movetext and no null moves. Combined with the completed legal replay, this verifies the imported corpus without changing its data. The stored full-game count and initial-position totals agree.

The first complete candidate passed all 87 browser flows. Root visual review then shortened the default lists to eight common moves and four examples, with explicit expansion controls, and cleared obsolete navigation toasts. The next protected recording exposed a pre-existing engine adapter mismatch: the final UCI bestmove could differ from the first line of the last complete MultiPV iteration, so practice correctly refused the inconsistent report. A deterministic native-process transcript reproduced the mismatch before the fix. The adapter now chooses a coherent iteration containing the chosen move and places that move’s own scored line first; it never attaches another move’s score or continuation. Saved practice can also select a matching line from older reports while still rejecting missing evidence. The failing regression, fixed regression and failed recording are retained with their status clearly separated.
